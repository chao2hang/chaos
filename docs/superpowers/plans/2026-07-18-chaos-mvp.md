# chaos MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a runnable chaos monorepo MVP: Rust REST API + SvelteKit UI + SQLite + latency tests + generate dae config and load/reload a bundled (or override) dae binary.

**Architecture:** Cargo workspace (`chaos-api`, `chaos-core`, `chaos-dae`, `chaos-store`) serves `/api/v1` on `127.0.0.1:2030`. SvelteKit app on `:5173` proxies API in dev. Data under `./data/`. dae binary from `scripts/fetch-dae.sh` or `CHAOS_DAE_BIN`.

**Tech Stack:** Rust 2021 / axum 0.8 / tokio / sqlx (SQLite) / argon2 / jsonwebtoken / reqwest / serde; SvelteKit 2 + TypeScript + pnpm; Linux first.

**Spec:** `docs/superpowers/specs/2026-07-18-chaos-product-design.md`

## Global Constraints

- Product path: `/home/chaos/projects/personal/chaos` (this repo only; do not modify `daed` for chaos work).
- Public API is **REST JSON** under `/api/v1` only — no GraphQL, no dae-wing dependency.
- Default API bind: **`127.0.0.1:2030`** (never default to 2023).
- Auth: **JWT** (HS256), 24h expiry, secret from `CHAOS_JWT_SECRET` or auto-generated file `./data/jwt.secret` for dev.
- Password hashing: **argon2**.
- DB: SQLite at `./data/chaos.db` (dev).
- Latency thresholds (frontend constants): green `< 200ms`, yellow `200–500ms`, red `> 500ms` or failed.
- MVP config template: fixed minimal dae config (direct + node outbounds + default route to proxy); no Group/Routing editors.
- dae: exec vendored/override binary; CI must not require real eBPF; mock binary OK for unit tests of `chaos-dae`.
- Commits: conventional (`feat:`, `fix:`, `chore:`, `docs:`, `test:`).
- YAGNI: no P3/P4 UI, no traffic charts, no multi-user RBAC.

## File map (MVP)

| Path | Responsibility |
